# 作业管理开发与测试记录

> 日期：2026-11-26  
> 阶段：核心业务开发第二模块  
> 结论：作业发布、提交、批改、退回、重交及附件鉴权已完成并通过真实数据库测试

## 1. 已完成功能

### 1.1 教师作业管理

- 教师只能选择本人有效任教的班级和学科。
- 创建作业草稿。
- 设置标题、内容、截止时间、满分和附件。
- 编辑草稿和已发布但未关闭的作业。
- 发布作业。
- 关闭作业。
- 删除草稿。
- 有人提交后禁止修改作业班级或学科。
- 已关闭作业禁止继续编辑。

### 1.2 学生提交

- 学生只能查看当前班级的已发布或已关闭作业。
- 提交文字内容和附件。
- 截止前可覆盖已提交内容，提交次数递增。
- 已批改作业不能直接重交。
- 教师退回后可重新提交。
- 退回后的重交次数和内容持久化保存。
- 提交附件与提交记录绑定。

### 1.3 教师提交清单与批改

- 提交清单覆盖当前班级全部学生。
- 状态包括未提交、已提交、已批改、已退回。
- 支持姓名和学号查询。
- 支持按提交状态筛选。
- 统计已交、已批改和未交人数。
- 成绩不能超过作业满分。
- 支持批改和修正成绩。
- 支持填写评语。
- 支持退回并填写退回原因。

### 1.4 家长查看

- 家长必须选择已绑定孩子。
- 只能查看该孩子当前班级的作业。
- 可查看作业要求、截止时间、提交状态、提交次数、成绩、评语和退回原因。
- 可下载孩子有权访问的作业及提交附件。
- 未绑定学生会返回 HTTP 403。

## 2. 后端接口

| 方法 | 路径 | 权限 |
|---|---|---|
| GET | `/api/assignments` | 已登录，按学生或孩子数据范围过滤 |
| GET | `/api/assignments/manage` | 教师 |
| GET | `/api/assignments/options` | 教师、家长 |
| GET | `/api/assignments/{id}` | 有作业访问权限 |
| POST | `/api/assignments` | 教师 |
| PUT | `/api/assignments/{id}` | 发布教师 |
| POST | `/api/assignments/{id}/publish` | 发布教师 |
| POST | `/api/assignments/{id}/close` | 发布教师 |
| DELETE | `/api/assignments/{id}` | 草稿发布教师 |
| GET | `/api/assignments/{id}/submissions` | 发布教师 |
| POST | `/api/assignments/{id}/submission` | 学生 |
| POST | `/api/submissions/{id}/grade` | 发布教师 |
| POST | `/api/submissions/{id}/return` | 发布教师 |

重点通过场景：

1. 教师向本人任教班级发布作业。
2. 教师向无关班级发布作业返回 HTTP 403。
3. 教师上传作业附件，学生发布后可下载。
4. 学生上传提交附件并提交作业。
5. 教师提交清单显示当前班级学生。
6. 绑定家长可下载孩子提交附件。
7. 超过作业满分的成绩返回 HTTP 400。
8. 教师批改后学生可查看成绩和评语。
9. 家长选择孩子后可查看已批改状态。
10. 家长查询未绑定孩子返回 HTTP 403。
11. 教师退回后学生重新提交，提交次数变为 2。
12. 通知、组织人员和认证既有回归测试继续通过。

## 5. 当前限制

1. 作业关闭目前由教师手动操作，系统不会在截止时间自动改变状态。
2. 同一学生保留一条当前提交记录，不提供每次提交的完整快照历史。
3. 已批改作业必须先由教师退回，学生才能重交。
4. 家长作业页面一次查看一个孩子，未提供多孩子合并统计。
5. 附件物理文件删除后不立即清理，后续增加定时清理任务。
