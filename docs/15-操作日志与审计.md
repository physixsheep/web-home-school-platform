# 操作日志与审计

## 1. 记录范围

已登录用户执行以下请求时自动写入 `operation_log`：

- `POST`
- `PUT`
- `PATCH`
- `DELETE`

登录接口在认证建立前执行，不记录为普通操作日志。匿名失败请求不会伪造用户日志。

## 2. 日志字段

| 字段 | 说明 |
|---|---|
| 用户 ID / 用户名快照 | 操作者身份 |
| 角色快照 | 请求发生时的角色 |
| 模块 | 用户、通知、作业、成绩、请假、成长、互动、附件等 |
| 操作 | 新增、修改、删除、发布、撤回、审批、批改、回复等 |
| HTTP 方法和路径 | 实际接口 |
| 查询参数 | 脱敏后保存 |
| HTTP 状态码 | 成功或失败结果 |
| IP 和 User-Agent | 客户端来源 |
| 耗时 | 请求耗时毫秒 |
| 创建时间 | 操作时间 |

密码、Token、Authorization 等查询参数会替换为 `***`。请求正文不写入日志。

## 3. 查询

管理员页面：

```text
/admin/operation-logs
```

接口：

```text
GET /api/admin/operation-logs
```

支持用户、模块、操作、路径、结果码和日期范围筛选。

## 4. 安全与可靠性

- 日志写入失败只记录服务端错误，不影响主业务返回。
- 日志查询仅管理员可访问。
- 日志不建立用户外键，避免账号删除影响历史审计快照。
- 当前采用同步写入；并发量增大后可调整为异步队列。
- 生产环境需设置日志保留周期和归档策略。
