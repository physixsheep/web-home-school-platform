- Swagger/OpenAPI 文档。

## 3. 实现说明

### 3.1 登录

`POST /api/auth/login`

1. Jakarta Validation 校验账号和密码参数。
2. Spring Security `AuthenticationManager` 调用用户详情服务。
3. 从数据库查询用户和角色。
4. BCrypt 校验密码，检查账号启用状态。
5. 更新最近登录时间。
6. JWT 写入用户 ID、角色、Token 版本、签发时间和过期时间。
7. 返回统一结果、Token 和当前用户资料。

### 3.2 请求认证

每次受保护请求：

1. 解析 `Authorization: Bearer <token>`。
2. 校验签名、签发方和过期时间。
3. 根据用户名重新读取数据库角色、账号状态和 Token 版本。
4. 用户 ID、版本或状态不匹配时不建立认证。
5. 未认证请求由统一入口返回 HTTP 401 JSON。

### 3.3 退出

`POST /api/auth/logout`

1. 获取当前登录用户。
2. 递增 `sys_user.token_version`。
3. 清理当前 SecurityContext。
4. 用户此前签发的所有 JWT 因版本不一致立即失效。

### 3.4 前端

- Pinia 保存 Token 和当前用户。
- Axios 请求拦截器附加 Bearer Token。
- 401 响应清理本地会话并返回登录页。
- Vue Router 根据角色路由元数据执行访问控制。
- 登录成功后按角色进入不同首页路径。
- 前端角色限制是体验层控制，后端仍对每个受保护接口执行认证和数据范围校验。

## 6. 手工验证

1. 按 README 初始化本机 MySQL。
2. 设置 `DB_USERNAME` 和 `DB_PASSWORD`。
3. 运行 `.\scripts\dev-backend.ps1`。
4. 运行 `.\scripts\dev-frontend.ps1`。
5. 访问 `http://127.0.0.1:5173`。
6. 使用四个测试账号依次登录，检查是否进入对应角色的首页。
7. 刷新页面，检查是否通过 `/api/auth/me` 恢复登录状态。
8. 点击退出，再在浏览器刷新，检查是否回到登录页。
9. 打开 `http://localhost:8080/swagger-ui.html`，使用登录得到的 Token 验证授权接口。

## 7. 当前已知事项

1. 本机默认 Java 为 8，直接执行 `mvn` 会使用错误 JDK；必须通过项目脚本或显式设置 `JAVA_HOME`。
2. 本机已有 MySQL 的 `root` 账号需要密码，项目未获取或保存该密码。
3. 开发环境 JWT 密钥有默认值；部署前必须通过 `JWT_SECRET` 替换。
4. Swagger 当前用于开发联调。进入生产部署阶段时应增加开关或网关访问限制。
5. 前端生产构建出现单个依赖块较大的性能提示，不影响功能。进入页面完善阶段后再做 Element Plus 按需加载和分包优化。
6. 本阶段页面只展示真实认证结果，不展示虚构的统计数字。
